# Claude Code 기본/경량 시스템 프롬프트 시간 비교

이 도구는 **실제 설치된 Claude Code + 기존 사내 API**를 사용합니다. Python 표준 라이브러리만 사용하며 pip 설치는 없습니다. `--run` 없이 모델을 호출하지 않습니다.

## 1. 준비

- Windows PowerShell, Python 3.10 이상 (`python`), 이미 인증 및 사내 모델 연결이 완료된 Claude Code.
- 이 ZIP은 테스트할 저장소 **밖의 별도 폴더**에 풀어 주세요. 예: `C:\tools\claude-timing`.
- 압축을 푼 폴더에서 아래 명령을 실행합니다.
- API 주소/키는 입력하거나 수정하지 않습니다. 기존 설정을 상속합니다. 사내 코드를 외부 API로 보내지 않도록 기존 연결을 확인하세요.
- `--model glm-5.3-flash`는 해당 ID를 사내 엔드포인트가 받을 때만 사용하세요. 별칭/모델 매핑을 이미 설정했다면 `--model` 옵션 전체를 생략해 기존 모델을 유지하세요.
- 새 세션을 매번 시작합니다. 기존 세션을 resume하지 않습니다.

## 2. 모델 호출 없는 점검

```powershell
python bench.py --self-test
python bench.py --repo "C:\work\my-project" --model glm-5.3-flash
```

첫 명령은 오프라인 테스트입니다. 외부 CLI나 모델을 사용하지 않고, 명시적으로 만든 테스트용 자식 프로세스로 스트림 파싱/시간 제한 등을 검증합니다. 이것은 GLM 벤치마크가 아닙니다. 두 번째 명령은 실행 계획만 출력합니다.

## 3. 짧은 실제 측정: 각 조건 한 번

아래부터 **실제 사내 모델 호출과 사용량 발생**:

```powershell
python bench.py --repo "C:\work\my-project" --model glm-5.3-flash --pairs 1 --run
```

기본 시스템 프롬프트와 경량 시스템 프롬프트로 같은 읽기 전용 과제를 실행합니다. README와 관련 파일을 읽고 한국어로 근거가 있는 요약을 만드는 과제입니다. 파일을 수정하거나 테스트/빌드 명령을 실행하는 에이전트 성능 평가는 아닙니다.

한 번의 호출 제한은 기본 300초, 15턴입니다. 시간 초과/턴 제한/오류는 실패로 기록하며, 빠른 정상 완료로 취급하지 않습니다.

## 4. 반복 측정

```powershell
python bench.py --repo "C:\work\my-project" --model glm-5.3-flash --pairs 4 --run
```

실행 순서: 기본→경량, 경량→기본을 반복합니다. 두 조건 모두 `high` effort, 같은 과제/도구/작업 폴더/기존 설정입니다. 변경 변수는 `--system-prompt-file`뿐입니다.

- 사내 서버가 effort를 실제로 반영하는지는 이 도구가 검증하지 못합니다.
- 서버 prefix cache와 OS 파일 캐시는 비우지 않습니다. 순서 교대만으로 캐시/부하 효과가 사라지지는 않습니다.
- 테스트 중 코드를 바꾸거나 다른 에이전트를 같은 폴더에서 실행하지 마세요.
- 동일 과제에서도 모델이 읽는 파일/호출 경로는 달라질 수 있습니다. 이는 관찰된 하네스 동작의 차이이며, 순수 prefill 속도 차이로 단정할 수 없습니다.
- 두 조건 모두 읽기 전용 기본 도구 `Read,Glob,Grep`만 노출하고 MCP를 제외합니다. 따라서 기본 조건도 평소의 모든 도구를 켠 Claude Code와 동일하지 않습니다.
- 사용자/프로젝트/관리자 설정 및 훅은 유지합니다. `--bare`나 권한 우회를 사용하지 않습니다. 기존 훅은 실행될 수 있으므로 신뢰하는 저장소에서 실행하세요. 읽기 전용 도구 제한은 훅까지 샌드박싱하는 기능이 아닙니다.

## 5. 결과

`results/<UTC 실행시각>/`에 저장됩니다.

- `metrics.csv`: 실행별 수치, Excel 호환 UTF-8 BOM.
- `summary.txt`: 조건별 중앙값, 실패 종류, 정상 완료 쌍의 시간 감소율.
- `*.answer.txt`: 답변 품질/근거를 직접 검토할 파일.
- `*.result.json`: CLI가 반환한 최종 결과 원본.
- `*.stdout.jsonl`, `*.stderr.log`: 개인 보관용 원본 로그.
- `metadata.json`: CLI 버전, 요청 모델, effort, 과제/경량 프롬프트 SHA-256, 순서.

주요 지표:

- `wall_s`: 프로세스 시작부터 종료까지 실제 경과 시간. CLI 시작/입력 처리/추론/도구/종료 오버헤드를 포함합니다.
- `api_s`: CLI의 `duration_api_ms`를 초로 변환한 값. 서버 GPU 계산시간만을 의미하지 않으며, CLI가 보고하지 않으면 빈칸입니다.
- `first_model_delta_s`: 첫 thinking 또는 text 스트리밍 조각을 로컬에서 관측하기까지. **서버 단독 TTFT가 아닙니다.**
- `first_text_delta_s`: 첫 텍스트 스트리밍 조각까지. 중간 설명일 수 있으므로 최종 답변 시작이라고 단정하지 않습니다.
- `first_tool_request_s`: 첫 도구 요청 이벤트를 관측하기까지. 실제 도구 실행 시작/완료 시각은 아닙니다.
- `tool_calls`: 관측된 고유 도구 호출 ID 수. `turns`: CLI가 보고한 턴 수.
- `input_tokens`, `output_tokens`, `cache_read_tokens`, `cache_write_tokens`: CLI 최종 usage에서 보고한 값. 미제공은 빈칸이고 0으로 추정하지 않습니다. `input_tokens`만으로 캐시 포함 전체 입력을 단정하지 마세요.
- `cost_usd`: CLI 보고값일 뿐 사내 청구 금액이 아닙니다. 0이 출력돼도 무료라는 뜻이 아닙니다.
- `reported_models`: CLI가 보고한 모델명. 서버가 실제로 실행한 체크포인트 검증은 아닙니다.
- `status=success`: CLI 정상 완료. 답변의 정확성/실제 과제 성공을 독립적으로 검증한 표시가 아닙니다.

`paired_wall_reduction_pct_median`은 두 조건이 모두 정상 완료한 각 쌍에 대해 `(기본 시간 - 경량 시간) / 기본 시간 * 100`을 계산한 뒤 중앙값을 냅니다. 양수면 경량이 빨랐습니다. 실패는 CSV와 전체 시도 시간 통계에 남습니다. 답변이 부실하거나 도구를 사용하지 않고 끝낸 경우 속도 개선으로 채택하지 마세요.

**원본 로그에는 사내 코드·프롬프트·경로가 포함될 수 있습니다. 외부 공유하지 마세요.** 공유가 필요하면 `summary.txt`와 민감한 모델명 등을 제거한 CSV만 검토하세요.

## 6. 문제 해결

- `unknown option`: `claude --version` 확인 후 사내 승인된 버전에서 해당 옵션 지원 여부를 확인하세요. 이 스크립트는 CLI를 자동 업데이트하지 않습니다.
- 모델 없음: `--model`을 사내 실제 ID로 바꾸거나 생략해 기존 매핑 사용.
- 명령 별칭/커스텀 래퍼: 일반 npm 설치와 실제 Claude 실행 파일을 지원합니다. 사용자 PowerShell alias/function은 상속하지 않습니다. 필요하면 `--claude-bin "C:\path\claude.exe"` 사용.
- 시간 제한: `--timeout 600`으로 늘리되 두 조건에 동일하게 적용.
- 턴 제한: `--max-turns 25`로 늘리되 제한 실패를 성공으로 재분류하지 마세요.
- 다른 읽기 전용 과제: UTF-8 파일 작성 후 `--task-file "C:\path\task.txt"`. 편집/빌드 과제는 이 번들 범위 밖입니다.
- 첫 응답/캐시 지표 빈칸: 서버/CLI가 이벤트나 카운터를 제공하지 않은 것입니다. 추정하지 않습니다.
- 기본 모델 설정은 복구할 필요가 없습니다. 원래 `claude`로 실행하면 기존 사용 방식 그대로입니다.

## 검증 범위

제작 환경 macOS에서 오프라인 단위 테스트, 테스트용 자식 프로세스를 통한 스트림/오류/시간 제한 처리, npm Windows shim 해석을 검증했습니다. 실제 Windows 런타임, 사내 GLM API, 모델 성능/속도는 사용자 환경에서 실행해야 검증됩니다. 테스트용 출력은 실제 벤치마크 결과가 아니며 ZIP에 결과 수치가 포함되지 않습니다.

공식 옵션 참고: https://code.claude.com/docs/en/cli-reference
