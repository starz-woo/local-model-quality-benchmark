# benchmark_custom_vs_claude.py — 사용자 제공 비교 실험

마지막 사용자 메시지의 HTML 이스케이프가 없는 두 번째 코드를 그대로 파일화했습니다.
첫 번째 코드에 있던 도구 설명을 두 번째 코드에 임의로 복구하거나 두 버전을 합치지 않았습니다.
기존 `bench.py`나 `agent.py`를 호출하는 통합 벤치마크가 아닌 독립 실행 스크립트입니다.

## 실행 전 주의

- 실행하거나 import하면 누락된 openai/rich를 현재 Python 환경에 pip로 자동 설치합니다. 별도 가상환경을 권장합니다.
- `setup_dirs()`는 현재 디렉터리의 `bench_custom_ws`, `bench_claude_ws`를 **재귀 삭제하고 다시 만듭니다**. 기존 작업/결과가 있는 위치에서는 실행하지 마세요.
- 실제 Claude 실행에 `--dangerously-skip-permissions`가 포함됩니다. 승인 절차와 보안 경계가 없으므로 폐기 가능한 격리 환경에서만 검토하세요. 저장소의 기본 실행 경로에는 연결하지 않았습니다.
- 모델·OpenAI 호환 주소·Anthropic 호환 주소를 상단에서 직접 맞춰야 합니다. 같은 모델명만으로 동일 가중치·양자화·옵션임을 증명하지 않습니다.
- 기존 CC Switch의 주소/모델 매핑을 그대로 유지하는 경로가 아닙니다. 환경변수와 --model을 설정합니다. localhost 주소의 Anthropic 호환 지원 여부를 별도로 확인해야 합니다.
- Windows npm Claude 실행 어댑터/프로세스 트리 종료 등 기존 bench.py의 보완을 이 원본에 적용하지 않았습니다.

```powershell
# 실제 실행: 패키지 설치, 작업 폴더 삭제, 모델 호출, 생성 코드 실행, 권한 우회 Claude 실행 포함
python benchmark_custom_vs_claude.py
```

## 결과를 검증된 성능 비교로 해석하지 마세요

원본의 아래 한계는 수정하지 않고 보존했습니다.

- 두 번째 코드의 CUSTOM_SYS_PROMPT에는 edit를 요구하면서 XML 없이 DONE만 답하라는 지시도 있고 구체적인 도구 형식 설명이 없습니다.
- custom은 과제당 모델을 한 번만 호출하고 Claude는 내부 에이전트 루프를 실행합니다. 동일한 실행 계약/예산 비교가 아닙니다.
- custom이 항상 먼저 실행되며 순서 무작위화·반복·캐시 적중 확인이 없습니다. `-c`는 대화 이어가기이지 KV 캐시 적중 보장이 아닙니다. `cache_prompt`도 서버별 지원 여부가 다릅니다.
- custom API 요청에는 명시적인 전체 실행 시간 제한이 없고, Claude 시간 제한/오류/미설치 처리와 대칭적이지 않습니다.
- Claude 프로세스 종료 코드를 확인하지 않고 출력 파일만 채점합니다. stdout 기대값 일치는 코드 품질이나 정상 에이전트 종료의 증거가 아닙니다.
- SEARCH가 맞지 않으면 replacement만으로 기존 파일을 덮어쓰는 fallback이 있습니다. 생성 코드 실행은 OS 샌드박스가 아닙니다.
- 동률도 Custom Wins로 표시하며, 시간 비율이 1 미만이어도 Custom is ... faster라고 표시합니다. 이 표기를 우세의 증거로 삼지 마세요.
- CLI 미설치가 0초 기록으로 나타납니다. 타임아웃/미실행을 성공 쌍의 속도 비교에 섞으면 안 됩니다.

## 오프라인 검사

`python scripts/run_tests.py`는 의존성·UI·모델을 모킹하고 설치/프로세스 실행을 차단해 이 파일의 구문과 임시 파일 edit 동작만 확인합니다.
실제 모델/Claude/검색 호출, 패키지 설치, 기본 작업 폴더 삭제는 하지 않습니다. 모델 속도·Windows E2E·캐시 효과는 미검증입니다.
