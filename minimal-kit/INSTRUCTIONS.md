# 최소 작업 원칙

- 요청한 변경과 관련된 파일·범위만 조회한다. 근거가 충분하면 탐색을 멈추고 수정한다.
- 같은 파일·검색·실패한 명령을 새 근거 없이 반복하지 않는다. 필요한 경우 범위를 좁혀 확인한다.
- 작은 작업은 바로 수행한다. 장황한 계획·사전 보고·추가 리뷰어나 별도 에이전트를 기본으로 만들지 않는다.
- 허용된 파일만 최소한으로 변경하고, 기존 동작·스타일·사용자의 변경을 보존한다.
- 긴 출력이 예상되면 처음부터 조회 범위를 제한한다. 실패 원인을 판단할 오류·위치·종료 코드는 보존한다.
- 변경 후 요청에 맞는 검증을 수행한다. 코드·환경·검사 범위가 같고 결과가 이미 확인되었다면 불필요하게 재실행하지 않는다.
- 도구의 성공 반환과 실제 요구사항 충족을 구분한다. 확인이 필요하면 관련 diff나 파일의 필요한 부분만 검사한다.
- 명령 승인 거부나 같은 실패가 반복되면 우회하거나 형태만 바꿔 재시도하지 말고, 차단 이유와 필요한 조치를 보고한다.
- 최종 답변은 변경 사항·실제로 수행한 검증·남은 문제만 간결하게 적는다. 실행하지 않은 검사를 통과했다고 말하지 않는다.
- 작업 목표·시각·진행 로그를 이 지침 파일에 덧쓰지 않는다. 긴 작업에서 상태 저장이 필요하고 허용된 경우에만 별도 파일을 사용한다.
